# 테스트 전략

## 1. 목표

테스트는 타입 체크나 빌드 통과를 실제 동작 검증으로 대신하지 않는다. 제품 위험을 기준으로 가장 싼 층에서 검증하고, 인증·동시성·외부 연동·핵심 사용자 흐름은 실제 경계까지 올려 검증한다.

## 2. 테스트 층

| 층 | 대상 | 예시 |
|---|---|---|
| 단위 | 순수 도메인·변환·UI 상태 | 모집 상태 전이, 경로 시간 계산, 태그 정규화 |
| 컴포넌트 | 접근성 있는 UI 동작 | 필터, 별점, 계획 항목 정렬, 오류 상태 |
| 저장소 통합 | 실제 PostgreSQL/PostGIS | 거리 검색, 커서, FK/UNIQUE, soft delete |
| API 통합 | FastAPI+DB+스토리지 fake | 인증, owner 권한, ETag, 멱등 키 |
| 계약 | OpenAPI·생성 클라이언트 | 요청/응답/enum/nullability 호환 |
| E2E 웹 | 실제 브라우저 | 가입→계획→공유→후기, 모집 신청 |
| E2E 모바일 | 실제/에뮬레이터 | 딥링크, 오프라인 계획, 위치·푸시 거부 |
| 비기능 | 성능·보안·접근성·복구 | 동시 수락, LCP, XSS, DB 복원 |

## 3. 도메인별 필수 사례

### 인증

- 인증 코드 만료·횟수·재전송 제한
- 비밀번호 재설정 시 계정 존재 비노출
- refresh 회전, 동시 요청, 이전 토큰 재사용 탐지
- 재인증 purpose·사용자 불일치
- 다른 사용자의 세션 삭제·프로필 수정 거부

### 교통·경로

- 분기 노선, 환승, 동일 역, 경로 없음
- 자정 이후 서비스 일자, 휴일 예외, 시발/종착 nullable 시각
- 실측 시간표와 추정 구간 혼합
- 동명이역 검색, 역 외부 ID 충돌
- 데이터 버전 변경 시 캐시 무효화

### 장소

- 1km 경계와 좌표계 정확도
- 카테고리·영업·bounds 조합 필터
- 지도 SDK 실패 시 목록 유지
- 중복 외부 장소 upsert와 retired 처리

### 계획

- 날짜 범위와 day 중복
- 항목 순서 중복·누락·원자 재정렬
- ETag 충돌과 사용자 선택 복구
- 공유 링크 만료·회수·복제 독립성
- 삭제된 장소/역 참조의 표시 정책

### 후기·미디어

- 평점 0.5 단위, 비용 0/nullable
- 태그 canonical 중복과 최대 개수
- 다른 사용자 미디어 claim 거부
- 악성/위장 파일, 업로드 중단, 고아 정리
- soft delete, 검색 제외, 관리자 복구

### 모집

- 작성자 자기 신청 금지, 중복 신청
- 마감 경계, 취소·재신청 정책
- 정원보다 작은 capacity 변경 거부
- 20개 이상의 병렬 수락에서 accepted가 capacity를 넘지 않음
- 모집 삭제·마감 시 알림 outbox 생성

## 4. 계약·DB 일관성

CI에서 자동 확인한다.

- OpenAPI enum ↔ Python enum ↔ DB CHECK/enum
- required/nullable ↔ DB nullability
- 최대 길이 ↔ DB 컬럼/도메인 규칙
- 모든 FK에 삭제 정책과 인덱스 존재 여부
- migration 후 ORM metadata와 예상 스키마 차이
- TypeScript 생성물에 미반영 diff가 없는지

## 5. 외부 연동

- adapter contract test는 저장된 비민감 fixture를 사용한다.
- provider sandbox smoke는 일정 실행하고 CI 필수 경로와 분리한다.
- timeout, 429, malformed payload, 오래된 데이터, 부분 누락을 주입한다.
- 실제 외부 장애에서도 마지막 성공 데이터와 기준 시각이 표시되는지 E2E로 확인한다.

## 6. 접근성·시각 검증

- axe 계열 자동 검사는 기본 위반을 잡고 수동 키보드·스크린리더 검증을 보완한다.
- 지도는 대체 목록 흐름을 E2E로 검증한다.
- 200% 확대, 좁은 화면, 긴 한국어 제목/태그, 다크 모드 시각 회귀를 포함한다.
- 이미지 snapshot 하나로 완료 판정하지 않고 실제 상호작용을 검증한다.

## 7. 성능

| 대상 | 초기 예산 |
|---|---|
| 공개 웹 p75 LCP | 2.5초 이하 |
| 웹 p75 INP | 200ms 이하 목표 |
| API 읽기 p95 | 외부 연동 제외 400ms 이하 |
| 경로 검색 p95 | 파일럿 데이터 1초 이하 |
| DB slow query | 500ms 이상 조사 |
| 모바일 cold start | 기준 기기·빌드에서 예산을 별도 고정 |

실제 데이터량의 최소 3~10배 합성 데이터로 cursor, FTS, 지도 bounds, 모집 동시성을 측정한다.

## 8. 릴리스 판정

- P0 E2E와 보안 핵심 음성 테스트 100% 통과
- severity 1/2 미해결 결함 0
- migration staging 적용·복원 성공
- 지원 지역 데이터 품질 검사 통과
- 접근성 핵심 흐름 심각 위반 0
- 관측 대시보드·알림·런북 확인

현행 기준선은 백엔드 55개 테스트가 통과했다. 이는 독립 버전의 기능 완료를 의미하지 않고 기존 구현 분석의 신뢰 근거로만 사용한다.
