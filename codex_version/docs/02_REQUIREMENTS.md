# 제품 요구사항

## 1. 우선순위 정의

- `P0`: 제품의 핵심 루프를 검증하기 위해 첫 공개 버전에 필수
- `P1`: P0 운영 데이터와 사용자 피드백 후 추가
- `P2`: 외부 연동·규모·운영 성숙도에 의존
- `OUT`: 현재 제품 경계 밖

## 3. 주요 비즈니스 규칙

1. 공개 탐색·후기·모집 목록은 비회원도 읽는다. 쓰기·저장·신청은 로그인한다.
2. 역은 외부 사업자 코드 하나로 식별하지 않는다. 내부 ID와 소스별 매핑을 분리한다.
3. 경로 결과는 알고리즘 버전, 계산 시각, 실측/추정 구간을 함께 반환한다.
4. 계획 항목 순서는 시각만으로 결정하지 않고 명시적 `position`으로 보존한다.
5. 모집 정원 수락은 게시글 잠금 또는 조건부 갱신으로 원자 처리한다.
6. 후기 평점은 API에서 1.0~5.0의 0.5 단위로 표현하고 DB에는 2배 정수로 저장한다.
7. 조회수는 중복 방지 정책을 적용한 이벤트 집계이며 상세 조회 트랜잭션을 잠그지 않는다.
8. 태그는 canonical 값과 표시 값을 구분한다.
9. 공개 공유 링크는 회수·만료가 가능하고 쓰기 권한을 절대 부여하지 않는다.
10. 관리자 삭제는 원칙적으로 숨김·감사 로그를 남기고, 불법·민감 데이터만 하드 삭제한다.

## 5. 충돌과 적용 결정

| 충돌 | 결정 |
|---|---|
| DB는 `WEEKEND`, 백엔드 계약은 `SATURDAY/HOLIDAY` | 목표 계약은 캘린더 기반 `serviceDate`와 `serviceType`; 단순 enum 의존 제거 |
| DB에서 `station_code` 삭제, 백엔드 응답에는 존재 | 내부 역 ID + `station_external_ids`로 분리 |
| 최신 DDL은 모집 전용, 과거 문서는 일반 게시판도 암시 | 모집은 P0, 토론형 커뮤니티는 별도 P1 리소스 |
| 회원 탈퇴 시 콘텐츠 연쇄 삭제 vs 커뮤니티 맥락 보존 | 개인정보 제거 후 작성자 익명화가 기본, 법적 삭제 요청은 별도 처리. 최종 법무 결정 `OPEN` |
| 현행 계획은 날짜·순번이 없음 | 목표 모델에 여행 기간·명시적 순번 추가 |

## 6. 2026-08-10 제품 경험 보강 요구사항

- 홈은 여행 시작 CTA, 추천 장소, 저장 인기 장소, 최신·인기 모집, 진행 중 이벤트와 공지를 한 화면에 제공한다.
- Web 주 메뉴 명칭은 `맵`, `내 일정`, `후기`, `모집`으로 통일한다.
- 맵은 맛집·카페를 기본 선택하며 카테고리를 복수 선택한다. 반경 원, 즐겨찾기 마커, 지도 이동 후 `이 영역 검색`을 제공한다.
- 장소 목록이나 마커를 선택하면 목록 옆 상세 패널에 주소·전화·카테고리·역 기준 도보 예상 시간을 표시한다. Kakao Local이 제공하지 않는 메뉴·가격·영업시간은 제공된 것처럼 표시하지 않는다.
- 시간표와 일정 편집기는 필요할 때만 우측 drawer로 연다. 외부 길찾기 CTA는 제거하고 선택 역에서 장소까지의 도보 맥락만 제공한다.
- 맵 일정 편집은 명시적 `STATION` 전환과 `PLACE` 방문 순서를 저장하며 시간 편집·재정렬·자동저장·번호 경로 집중 모드를 지원한다.
- 후기에는 도착역이 없는 단일 역 여행을 허용한다. 목록은 이미지 비율 기반 masonry, 이미지 위 역 배지, 본문 미리보기 제거를 적용한다.
- 모집 목록은 카드 격자 대신 최신·인기·마감 임박 정렬이 있는 단일 소셜 피드로 제공한다.
