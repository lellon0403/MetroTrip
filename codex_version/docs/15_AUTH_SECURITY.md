# 인증·보안 명세

## 1. 보안 목표

1. 계정·세션 탈취의 피해 범위를 기기와 세션 단위로 제한한다.
2. 위치·연락처·여행 일정의 수집과 노출을 최소화한다.
3. 사용자 콘텐츠와 미디어를 신뢰하지 않고 검증한다.
4. 작성자·신청자·관리자 권한을 서버에서 일관되게 강제한다.
5. 사고 조사와 복구에 필요한 감사성을 제공하되 민감 내용을 로그에 남기지 않는다.

## 2. 인증 모델

- 액세스 토큰: 15분 수명, `iss/aud/sub/iat/exp/jti` 필수 검증. 초기 HS256 구현은 production secret manager 값을 사용하고 향후 key rotation 시 `kid`를 추가한다.
- 리프레시 토큰: 14~30일, 매 사용 회전, DB에는 SHA-256 계열 단방향 hash만 저장.
- token family: 이전 토큰 재사용이 감지되면 해당 기기 family 전체를 폐기하고 사용자에게 알린다.
- 웹: refresh는 `HttpOnly; Secure; SameSite=Lax` 쿠키, access는 메모리 중심.
- 모바일: refresh는 OS 보안 저장소, 기기 ID와 세션을 묶는다.
- 서버 서명 키는 비밀 관리 시스템에 보관하고 `kid` 기반 단계적 회전을 지원한다.
- `environment`가 local/test가 아니면 개발 기본 DB/JWT/S3/push secret, 비보안 cookie, HTTP Web origin 중 하나라도 남아 있을 때 API 설정 검증이 부팅을 거부한다.

`CONFLICT` 현행 프론트는 access/refresh 모두 `localStorage`에 저장한다. 목표 버전에서는 XSS 탈취 범위를 줄이기 위해 사용하지 않는다.

## 3. 비밀번호·검증

- 비밀번호는 검증된 Argon2id 또는 scrypt 구현으로 hash하며 매개변수를 버전과 함께 저장한다.
- 길이 중심 정책을 사용하고 유출 비밀번호 차단 여부는 개인정보 전송 방식 검토 후 결정한다.
- 이메일 인증 코드는 짧은 수명, 시도 제한, 재전송 제한을 둔다.
- 계정 존재 여부가 비밀번호 재설정 응답·소요시간으로 노출되지 않게 한다.
- 프로필 민감 변경, 비밀번호 변경, 전체 세션 종료는 목적이 들어간 5분 재인증을 목표로 한다. 현재 탈퇴 API는 재사용 가능한 재인증 토큰 대신 현재 비밀번호와 정확한 `DELETE` 확인 문구를 요청 본문에서 함께 검증한다.
- 비밀번호 변경·재설정 후 기존 세션을 폐기한다.

## 4. 권한

| 역할/조건 | 권한 |
|---|---|
| PUBLIC | 공개 역·장소·후기·모집·공유 계획 읽기 |
| USER | 즐겨찾기·계획·후기·모집·신청·알림 |
| OWNER | 자기 리소스 수정·삭제·공유·신청 관리 |
| MODERATOR | 신고 읽기, 콘텐츠 숨김/복구, 제재 |
| PLACE_EDITOR | 장소 초안·수정 |
| PLACE_PUBLISHER | 장소 게시 승인 |
| ADMIN | 역할 관리 등 제한된 운영 권한 |

- UI 숨김은 보안 통제가 아니다. 모든 API에서 resource ownership과 scope를 검사한다.
- 관리자도 자기 권한을 올리거나 감사 로그를 수정할 수 없다.
- 대량 export, 역할 변경, 영구 삭제는 재인증과 사유를 요구한다.

## 5. CSRF·CORS·XSS

- 웹 쿠키 인증 상태 변경 요청은 SameSite, Origin/Referer 검증, CSRF 토큰을 조합한다.
- CORS origin은 환경별 명시 목록이며 wildcard+credentials를 금지한다.
- 사용자 본문은 제한된 구조화 문서로 저장하고 서버/클라이언트 렌더러 모두 allowlist를 사용한다.
- 외부 링크는 안전한 scheme만 허용하고 새 창에는 `noopener noreferrer`를 적용한다.
- CSP는 nonce 기반 script 정책, object 차단, frame-ancestors 제한으로 시작한다.
- 지도/미디어 공급자 도메인은 최소한으로 CSP에 추가한다.

## 6. 미디어 보안

1. 업로드 의도를 API가 발급하고 사용자·목적·크기·MIME·만료를 고정한다.
2. 객체 저장소는 비공개 기본, 업로드 경로는 추측 불가능한 키를 사용한다.
3. 완료 후 실제 파일 signature, 크기, 이미지 디코딩, 악성 파일 검사를 수행한다.
4. EXIF 위치정보를 제거하고 안전한 이미지 변형을 생성한다.
5. 검증 전 파일은 공개 CDN에서 제공하지 않는다.
6. 고아 업로드와 삭제 미디어는 수명주기 작업으로 정리한다.

## 7. 위치·개인정보

- 가까운 역 기능은 foreground 위치 1회 사용이 기본이다.
- 정확한 위치를 사용자 프로필이나 행동 로그에 저장하지 않는다.
- 분석에는 역/지역 수준으로 축약하거나 기기에서 계산한다.
- 여행 계획의 공개 범위는 `PRIVATE/UNLISTED/PUBLIC`로 분리하고 기본은 PRIVATE다.
- 공유 링크는 회수·만료 가능하고 검색 인덱싱하지 않는다.
- 모집글에 전화번호·메신저 ID 직접 기재를 유도하지 않는다.
- 개인정보 보존 기간과 탈퇴 정책은 출시 전 법무·운영 승인이 필요하다(`OPEN`).

## 8. 남용 방지

| 대상 | 통제 |
|---|---|
| 로그인·검증 코드 | IP+계정+기기별 속도 제한, 점진 지연 |
| 검색·지도 | IP/사용자 quota, bounds/radius 제한, 캐시 |
| 글·댓글·신청 | 신규 계정 제한, 중복·burst 탐지 |
| 미디어 | 사용자 quota, MIME/크기 제한, 검사 |
| 신고 | 중복 방지와 악용 모니터링 |
| 관리자 | SSO/MFA 권장, IP/기기 정책 선택, 모든 변경 감사 |

CAPTCHA는 기본 마찰로 넣지 않고 공격 신호가 임계값을 넘을 때 단계적으로 적용한다.

## 9. 비밀·로그

- 비밀은 저장소·이미지·프론트 번들에 넣지 않고 환경별 비밀 관리 시스템에서 주입한다.
- 지도 브라우저 키처럼 공개될 수밖에 없는 키는 도메인·앱 서명·quota로 제한한다.
- 로그 금지: 토큰, 비밀번호, 인증 코드, 이메일 본문, 정확한 위치, 사용자 작성 본문, push token.
- 이메일·사용자 ID는 필요 시 안정된 비가역 식별자로 마스킹한다.
- 감사 로그는 actor, action, resource, reason, request ID, 전후 변경 요약을 기록한다.

## 10. 위협과 검증

| 위협 | 주요 방어 | 필수 테스트 |
|---|---|---|
| refresh token 탈취·재사용 | 회전/family/reuse 탐지 | 동시 refresh와 재사용 통합 테스트 |
| IDOR | 서버 owner/scope 검사 | 다른 사용자 ID 전수 음성 테스트 |
| 모집 정원 경쟁 | 행 잠금·조건부 갱신 | 병렬 수락 부하 테스트 |
| 저장형 XSS | 구조화 본문·allowlist·CSP | 악성 payload 렌더 테스트 |
| 임의 파일 업로드 | signature 검사·비공개 quarantine | 확장자 위장·초대형 파일 테스트 |
| 공유 토큰 추측/유출 | 충분한 엔트로피·hash·회수 | 만료/회수/로그 마스킹 테스트 |
| 관리자 오남용 | scope·재인증·감사 | 권한 조합·감사 불변 테스트 |

보안 사고 대응 연락망, 키 회전, 세션 강제 폐기, 사용자 통지 절차는 운영 런북으로 별도 작성한다.
