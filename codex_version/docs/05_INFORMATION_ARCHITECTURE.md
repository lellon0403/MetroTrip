# 정보 구조

## 공통 도메인 객체

`노선 → 역 → 장소 → 계획 → 후기/모집`이 주 연결축이다. 사용자, 알림, 신고는 이 축을 지원한다.

## 웹 IA

```text
탐색
├─ 노선도
├─ 역 검색
├─ 역 상세
│  ├─ 주변 장소
│  ├─ 시간표
│  └─ 관련 후기
└─ 장소 상세
경로
├─ 경로 검색
└─ 경로 비교
여행 계획
├─ 내 계획
├─ 계획 편집
└─ 공유 계획
커뮤니티
├─ 후기
│  ├─ 목록/상세
│  └─ 작성/수정
├─ 이야기(P1)
└─ 동행 모집
마이
├─ 프로필/보안
├─ 즐겨찾기
├─ 내 후기
├─ 내 모집/참여
└─ 알림
관리(P1)
├─ 장소/공지
├─ 신고/제재
└─ 감사 로그
```

웹 1차 내비게이션은 `탐색`, `경로`, `계획`, `커뮤니티` 네 개다. 로그인 상태에서 `마이`와 알림을 우측 유틸리티에 둔다. 노선도와 지도는 서로 다른 최상위 메뉴가 아니라 탐색의 두 진입 방식이다.

## 모바일 IA

하단 탭은 다섯 개로 제한한다.

| 탭 | 기본 화면 | 이유 |
|---|---|---|
| 홈 | 오늘 계획·가까운 역·최근 저장 | 현장 맥락 우선 |
| 탐색 | 지도·역/장소 검색 | 한 손 탐색 |
| 계획 | 저장 계획·당일 모드 | 실행 빈도 높음 |
| 커뮤니티 | 후기·모집 | 소비·상태 확인 |
| 마이 | 즐겨찾기·알림·설정 | 계정 작업 묶음 |

경로 검색은 탐색과 계획에서 모두 진입하지만 하나의 화면 스택을 사용한다. 후기 작성은 중앙 고정 탭으로 두지 않고 여행 완료·후기 상세·마이에서 문맥적으로 시작한다.

## URL·딥링크 규칙

| 리소스 | 웹 | 앱 딥링크 |
|---|---|---|
| 역 | `/stations/{stationSlug}` | `metrotrip://stations/{id}` |
| 장소 | `/places/{placeId}` | `metrotrip://places/{id}` |
| 경로 검색 | `/routes?from=&to=&departAt=` | `metrotrip://routes?...` |
| 계획 | `/plans/{planId}` | `metrotrip://plans/{id}` |
| 공유 계획 | `/shared/plans/{token}` | HTTPS universal/app link |
| 후기 | `/reviews/{reviewId}` | `metrotrip://reviews/{id}` |
| 모집 | `/recruitments/{postId}` | `metrotrip://recruitments/{id}` |

slug는 표시·SEO용이며 서버 식별은 ID로 한다. 동명이역은 노선·도시를 보조 표시한다.

## 검색 정보 구조

통합 검색은 한 입력창으로 시작하되 결과를 섞어 무한 나열하지 않는다.

1. 빠른 제안: 역, 장소, 최근 검색
2. 전체 결과 탭: 역 / 장소 / 후기 / 모집
3. 각 결과에 리소스 유형, 위치 문맥, 핵심 메타데이터 표시

`OPEN` 커뮤니티 전체 텍스트 검색은 P1에서 PostgreSQL FTS로 시작할지 외부 검색엔진을 도입할지 데이터량 기준을 정한다.

## 권한별 노출

| 영역 | 비회원 | 회원 | 작성자 | 관리자 |
|---|---|---|---|---|
| 탐색·시간표 | 읽기 | 읽기·저장 | 동일 | 데이터 편집 별도 화면 |
| 계획 | 공유본 읽기 | 내 계획 CRUD·복제 | 공유 회수 | 신고 대응만 |
| 후기 | 읽기 | 작성·반응 | 수정·삭제 | 숨김·복구 |
| 모집 | 읽기 | 신청·작성 | 신청 관리 | 숨김·강제 마감 |
| 알림 | 없음 | 내 알림 | 동일 | 시스템 발송 권한 제한 |

## 8. Web 제품 내비게이션 확정

- 홈 `/`: 여행 시작, 추천·인기 장소, 모집 하이라이트, 이벤트·공지.
- 맵 `/discover`: 역 strip → 장소 목록 → 장소 상세 → 지도 → 선택형 시간표/일정 drawer.
- 내 일정 `/plans`, 후기 `/reviews`, 모집 `/recruitments`, 마이 `/my`.
- `동행`은 사용자 노출 문구에서 `모집`으로 통일한다. 내부 API 리소스명 `recruitments`는 유지한다.
