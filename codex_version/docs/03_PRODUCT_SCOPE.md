# 제품 범위

## 릴리스 전략

지역·데이터·기능을 동시에 넓히지 않는다. 한 단계에서 “탐색→계획→공유” 루프를 실제 데이터로 완성한 뒤 지역과 커뮤니티를 확장한다.

## Phase 0 — 기반 검증

목표: 천안·아산 또는 합의된 파일럿 구간에서 신뢰 가능한 지하철 여행 루프를 공개한다.

포함:

- 이메일 인증·세션·프로필
- 노선/역 검색, 노선도, 역 상세, 시간표
- 역 주변 장소 지도·목록·필터·상세
- 역·장소 즐겨찾기
- 출발/도착 경로 비교
- 날짜·순서가 있는 여행 계획 CRUD, 공유·복제
- 후기 목록/상세/작성/수정/삭제, 이미지·태그
- 동행 모집 CRUD와 신청 상태 관리
- 마이페이지 통합 조회
- 반응형 웹, 다크 모드, 운영 최소 도구

제외:

- 실시간 열차 위치
- 소셜 로그인
- 네이티브 앱
- 푸시 알림
- 영상
- 범용 토론 게시판과 댓글
- 자동 추천·AI 일정 생성

## Phase 1 — 현장 사용과 커뮤니티

목표: 여행 당일 사용성과 사용자 간 재사용 루프를 강화한다.

- Expo 기반 iOS/Android 앱
- 위치 기반 가까운 역, 계획 오프라인 캐시
- 인앱·푸시·이메일 알림
- 카카오·네이버 로그인
- 후기 도움됨 반응, 댓글·질문/팁 게시판
- 신고·제재·관리자 감사 화면
- 장소 데이터 동기화 자동화와 품질 신고
- 계획 템플릿·복제 출처 표시

## Phase 2 — 교통 정밀도와 확장

목표: 지원 노선 확대와 외부 운행 데이터 기반 정밀도를 높인다.

- 실시간 도착·열차 위치(공급 계약과 SLA 확보 시)
- 전체 수도권 주요 노선, 환승·급행·운휴 반영
- 개인화 추천(충분한 행동 데이터와 동의 후)
- 영상, 다국어, 고급 운영 자동화
- 부하와 조직 규모가 증명될 때 서비스 분리 검토

## 범위 밖

| 항목 | 이유 |
|---|---|
| 숙소·교통권 결제 | 결제·환불·정산·규제 도메인이 핵심 검증을 압도함 |
| 사용자 간 송금/회비 | 에스크로·분쟁·본인인증 필요 |
| 차량 경로 | 지하철 중심 가치와 충돌 |
| 무제한 외부 장소 수집 | 라이선스·중복·품질 비용 통제 불가 |
| 자체 메신저 | 신고·보존·실시간 인프라 비용이 큼. 초기에는 상태 알림과 공개 댓글로 제한 |
| Kubernetes | 초기 트래픽·팀 규모에서 운영 비용이 가치보다 큼 |
| MySQL→Oracle 실시간 이중화 | 복구 목표를 만족하는 관리형 DB 백업·복제보다 복잡함 |

## 출시 게이트

Phase 0 공개 전 모두 충족한다.

1. 지원 지역과 시간표 기준일을 화면에서 확인할 수 있다.
2. 역·장소·경로 API의 5xx 비율과 무결과율을 관측한다.
3. 회원가입→계획 공유→후기 작성 E2E가 통과한다.
4. 모집 정원 동시성 테스트가 통과한다.
5. 접근성 핵심 흐름에 심각도 높은 위반이 없다.
6. 개인정보 처리·탈퇴·신고·운영자 권한 정책이 승인된다.
7. 백업 복원 리허설이 성공한다.

## 지역 확장 기준

- 역·노선 위상 데이터 완전성 99% 이상
- 시간표 커버리지와 결측 구간 공개
- 역별 장소 최소 품질 기준 충족
- 외부 데이터 라이선스 확인
- 파일럿 지역 핵심 루프 완성률과 오류 예산 충족

`OPEN` 파일럿 지역은 기존 자산이 강한 천안·아산이 기본안이나, 사용자 모집 가능성과 실사용 빈도를 함께 평가해야 한다.
