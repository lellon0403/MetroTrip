# 사용자 흐름

## 1. 비회원 탐색에서 계획 시작

1. 사용자가 검색 또는 노선도에서 역을 선택한다.
2. 역 상세에서 지도와 주변 장소를 동시에 탐색한다.
3. 카테고리·거리·영업 상태를 필터링한다.
4. 장소 상세에서 후기와 교통 정보를 확인한다.
5. `계획에 담기`를 누른다.
6. 비회원이면 현재 선택을 임시 보관한 채 로그인/가입을 요청한다.
7. 인증 후 원래 문맥으로 돌아와 새 계획 또는 기존 계획에 추가한다.

실패 복구:

- 위치 권한 거부: 역 검색을 기본 경로로 제공한다.
- 장소 무결과: 반경 확대, 필터 초기화, 인접 역을 제안한다.
- 인증 취소: 임시 선택은 브라우저 세션 동안 유지한다.

## 2. 경로에서 여행 계획 만들기

1. 출발역·도착역·출발 시각을 입력한다.
2. 빠른 경로와 적은 환승 경로를 비교한다.
3. 사용자는 실측/추정 구간과 대기 시간을 확인한다.
4. 한 경로를 선택하면 경유역 타임라인이 열린다.
5. 경유역별 장소를 추가하고 방문 순서를 드래그 또는 버튼으로 조정한다.
6. 날짜·체류 시간·메모를 입력한다.
7. 충돌 검증 후 저장한다.
8. 읽기 전용 링크를 발급하거나 후기/모집에 연결한다.

예외:

- 시간표 없음: 추정 근거와 불확실성을 표시한다.
- 막차 이후: 다음 서비스 일자 또는 시간 미지정 경로를 제안한다.
- 같은 시각 충돌: 자동 보정하지 않고 충돌 위치와 수정안을 보여준다.

## 3. 후기 작성

1. 사용자가 여행 완료 계획 또는 빈 후기를 선택한다.
2. 계획을 선택하면 경로·날짜·장소를 초안에 연결한다.
3. 제목, 본문, 평점, 비용, 태그를 입력한다.
4. 이미지는 먼저 임시 업로드하고 본문/갤러리에 배치한다.
5. 미리보기에서 공개 범위와 연결된 계획을 확인한다.
6. 저장 시 후기와 미디어 연결을 하나의 논리 작업으로 확정한다.
7. 상세 페이지에서 공유하거나 계획 복제를 허용한다.

예외:

- 업로드 실패: 성공한 파일은 유지하고 실패 파일만 재시도한다.
- 이탈: 로컬 초안 복원을 제안한다.
- 계획 비공개: 후기에는 공개 가능한 스냅샷만 포함한다.

## 4. 동행 모집

1. 작성자가 자신의 계획을 선택하거나 일정 정보를 직접 입력한다.
2. 제목·설명·정원·마감·여행일을 설정하고 게시한다.
3. 신청자는 계획 요약과 남은 자리를 확인하고 신청한다.
4. 작성자는 신청 목록에서 수락·거절한다.
5. 수락 트랜잭션이 정원을 검사하고 마지막 자리면 자동 마감한다.
6. 신청자에게 상태 알림이 생성된다.
7. 작성자 또는 정책 작업이 모집을 닫는다.

상태 전이:

- 모집: `DRAFT → RECRUITING → CLOSED | CANCELED`
- 신청: `APPLIED → ACCEPTED | REJECTED | CANCELED`
- 거절·취소 후 재신청 허용 여부는 [99_OPEN_QUESTIONS.md](99_OPEN_QUESTIONS.md)의 정책 결정 대상이다.

## 5. 여행 당일 모바일 흐름

1. 앱 홈이 오늘 계획과 가까운 역을 우선 표시한다.
2. 사용자는 계획을 열고 현재 항목·다음 이동을 확인한다.
3. 역 도착 시 시간표와 출구/주변 장소를 확인한다.
4. 네트워크가 불안하면 마지막 동기화 계획·역·장소 요약을 읽는다.
5. 항목 완료를 로컬에서 표시하고 연결되면 동기화한다.
6. 여행 종료 후 후기를 작성하도록 한 번만 안내한다.

## 6. 계정과 세션 복구

1. 보호 API가 액세스 토큰 만료를 반환한다.
2. 클라이언트는 진행 중 요청을 하나의 갱신 요청 뒤에 대기시킨다.
3. 서버는 리프레시 토큰을 회전한다.
4. 성공하면 원 요청을 한 번 재시도한다.
5. 재사용 탐지·만료·폐기면 세션을 지우고 현재 위치를 보존한 로그인 화면으로 이동한다.

## 7. 관리자 처리

1. 신고 큐에서 대상·사유·이력을 본다.
2. 원문, 연결 리소스, 작성자 제재 이력을 검토한다.
3. 기각·숨김·복구·계정 제한 중 하나를 사유와 함께 실행한다.
4. 감사 로그와 사용자 통지 이벤트가 남는다.
5. 장소 수정은 원본 출처와 변경 전후 값을 비교한 뒤 게시한다.
