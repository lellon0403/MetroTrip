# MetroTrip — MVP 명세서 (프론트엔드)

> 이 문서가 **MVP 개발의 유일한 기준(Single Source of Truth)** 입니다.
> 여기 없는 기능은 발표 전까지 만들지 않습니다. 범위 변경은 반드시 이 문서를 먼저 수정하고 PR에 링크합니다.

- 최종 수정: 2026-07-26 (상단 내비 전환, 마이페이지·수도권 노선도 추가)
- 상태: 확정 (v1.2)
- 담당: 프론트엔드 (우진, 황지성)

---

## 1. 목표

자가용이 없는 사용자가 **지하철 역을 선택하면, 그 역 주변 1km의 가볼 만한 장소가 지도에 표시되는** 웹 앱.
1주일 안에 **발표에서 시연 가능한 MVP**를 만드는 것이 목표입니다.

## 2. MVP 범위 (딱 이것만)

| # | 기능 | 완료 기준 (Definition of Done) |
|---|---|---|
| F1 | 역 선택 | 목록 또는 검색으로 역을 고를 수 있다 |
| F2 | 지도 이동 | 역 선택 시 카카오맵이 그 역 좌표로 중심 이동한다 |
| F3 | 주변 장소 표시 | 반경 1km 내 음식점·카페·관광명소를 마커로 표시한다 |
| F4 | 장소 상세 | 마커 클릭 시 장소명·주소를 인포윈도우로 보여준다 |
| F5 | 반응형 | PC(1920px)/모바일(360px)에서 레이아웃이 깨지지 않는다 |

## 2-1. 발표용 프리뷰 화면 (동작하지 않음)

발표에서 **"다음 단계에는 이런 걸 만듭니다"** 를 보여주기 위한 화면입니다.
F1~F5와 달리 **실제로 동작하지 않아도 됩니다.** 정지된 화면(목업)이면 충분합니다.

| # | 화면 | 완료 기준 |
|---|---|---|
| P1 | 노선도 | 1호선 천안·아산 구간 + 수도권 간략 노선도가 보인다 |
| P2 | 경로 | 출발역·도착역을 고르는 화면 구성이 보인다 |
| P3 | 시간표 | 역별 시간표 화면 구성이 보인다 |
| P4 | 마이페이지 | 즐겨찾기·후기·계정 관리 화면 구성이 보인다 |

- 이 화면들은 **"준비중" 표시를 명확히** 해서, 데모 중 실제 기능으로 오해받지 않게 합니다.
- 데이터는 하드코딩해도 됩니다. 단, **거짓 정보로 보이지 않게** 예시임을 화면에 밝힙니다.
  (특히 시간표는 실제 운행 시각 데이터가 없으므로 반드시 예시 표기)
- 설계 근거: `docs/UIUX-설계도.docx` / 관련 논의는 [REQUIREMENTS.md](REQUIREMENTS.md)의 P1·P2 항목.

### 수도권 노선도 — 이미지 + 끌어보는 뷰어

`frontend/public/metro-map.png` 한 장을 지도처럼 **끌어서 움직이고 휠로 확대**해서 봅니다
(`frontend/src/components/LineMap/MetroMapPanel.tsx`).

- 스크롤바 대신 **잡아 끌기**로 움직입니다. 노선도는 세로로도 길어서
  가로 스크롤바만으로는 아래쪽을 보기 어려웠습니다.
- 처음에는 **가로를 꽉 채우는 배율**로 보여줍니다. 세로까지 다 넣으면
  양옆이 크게 비고 역 이름이 작아집니다.
- 단, 폰 화면 폭(약 310px)에 맞추면 역 이름을 전혀 못 읽으므로
  **최소 900px 폭은 유지**하고 화면 밖으로 나가는 부분은 끌어서 봅니다.
- 확대 한계는 원본 크기(100%)입니다. 그 이상은 뭉개집니다.
- 이미지는 **팔레트 PNG로 압축**해서 넣습니다 (2.8MB → 631KB). 원본을 그대로 올리면 느립니다.
- 이미지 경로는 반드시 `frontend/src/lib/asset.ts`의 `asset()`을 거칩니다.
  GitHub Pages가 `/MetroTrip/` 하위로 서비스되기 때문에 `/metro-map.png`로 적으면 배포본에서 404가 납니다.

> 이전에 직접 그린 SVG 도식 노선도(`metroLines.ts` / `MetroMap.tsx`)가 있었으나,
> 실제 노선도 이미지로 대체하면서 **제거**했습니다. 필요하면 git 이력에서 되살릴 수 있습니다.

## 3. 범위 밖 (지금 만들지 않음)

로그인/회원가입, 소셜로그인, 후기 게시판, 소모임, 즐겨찾기, 여행 동선 계획,
실시간 지하철 위치, 다크모드, 관리자 기능, 친구 추가,
**백엔드 서버, 데이터베이스**.

**노선도·경로·시간표·마이페이지의 실제 동작**(경로 계산, 실제 시간표 조회,
전체 노선 데이터, 로그인·회원 데이터)도 범위 밖입니다.
위 2-1은 **화면만** 만드는 것이며, 기능 구현은 백엔드 연동 이후입니다.

→ 전부 발표 이후 작업입니다. 전체 요구사항과 단계별 계획은 [REQUIREMENTS.md](REQUIREMENTS.md) 참고.

## 4. 기술 스택

- React + Vite + TypeScript
- 카카오맵 JavaScript SDK + 카카오 로컬(Places) 검색
- 백엔드 없음 — 프론트에서 카카오 API 직접 호출
- 상태관리는 `useState`로 충분. 라이브러리 추가 최소화 (추가 시 PR에서 사유 명시)

## 5. 카카오맵 연동 방법

- SDK는 `index.html`에 script 태그로 로드 (`appkey` = JavaScript 키, `libraries=services`)
- 지도 표시: `kakao.maps.Map`
- 주변 장소 검색: `kakao.maps.services.Places`의 `categorySearch`
  - 카테고리 코드: `FD6`(음식점), `CE7`(카페), `AT4`(관광명소)
  - 옵션: 중심 좌표 = 선택한 역, `radius: 1000`
- 검색 결과를 마커로 표시, 마커 클릭 시 인포윈도우로 장소명/주소 노출

> **지금 상태(발표용)**: 카카오 검색을 매번 호출하지 않고, 탕정역 두 곳
> (써브웨이 아산탕정점 / 매화공원)만 `frontend/src/data/places.json`에 넣어 두고 마커로 찍습니다.
> 좌표·주소는 카카오 로컬 검색으로 실제 값을 확인해 넣었습니다.
> 데이터 형태는 **나중에 백엔드가 내려줄 응답에 맞춰** 잡아 뒀으므로
> (`frontend/src/types/place.ts`), 연동 시 `frontend/src/api/places.ts` 내부만 fetch로 바꾸면 됩니다.
>
> 참고: 지도에 원래 보이는 상점 아이콘들은 **카카오가 그린 것이라 우리가 클릭 이벤트를
> 붙일 수 없습니다.** 클릭이 되는 건 우리가 직접 찍은 마커뿐입니다.

## 6. 역 데이터

- 백엔드/DB 없이 프론트에 **정적 JSON**으로 둔다 (`frontend/src/data/stations.json`)
- **수도권 전철 1호선** 중에서도 **충남권(천안·아산 구간)** 을 우선 채운다
- 최종 목표는 전체 노선이지만, 프로젝트 기간이 3주이므로 **1호선 → 그중 충남권 구간** 순으로 좁힌다

### 우선 포함할 역 (데모 핵심)

| 역명 | 비고 |
|---|---|
| 탕정역 | 초기 렌더 기준 |
| 아산역 | KTX 천안아산역과 연결된 1호선 역 |
| 배방역 | |
| 온양온천역 | 주변 장소 풍부 — 데모 효과 좋음 |
| 천안역 | 1호선 주요 역 |
| 두정역 / 봉명역 / 쌍용역 / 신창역 | 여유 되면 추가 |

> **주의**: `천안아산역`은 KTX/SRT 전용역이라 1호선 역이 아닙니다.
> 1호선에서 여기에 해당하는 역은 **아산역**(도보 연결)입니다.
> 데이터에는 `아산역`으로 넣되, 검색 편의를 위해 별칭 처리는 추후 고려합니다.

- 데이터 형식:

```ts
type Station = {
  name: string;   // 역명 (예: "서울역")
  lat: number;    // 위도
  lng: number;    // 경도
  line: string;   // 노선 (예: "1호선")
};
```

- 좌표는 실제 값으로 채운다. 초기 렌더 기준 역: **탕정역**
- 노선 확장은 **JSON에 데이터만 추가**하면 되도록 만든다 (코드 수정 없이)

## 7. 화면 구성

Stitch 디자인 적용 후 구조 (2026-07-26 갱신):

- **상단 가로 내비게이션**: 지도 / 노선 / 경로 / 시간표 / 마이페이지
  - `지도`만 실제 기능이고, 나머지 넷은 2-1의 프리뷰 화면
  - 원래 좌측 사이드바였으나, 화면을 넓게 쓰려고 상단으로 옮겼습니다
  - 좁은 화면(`sm` 미만)에서는 글자를 숨기고 아이콘만 남깁니다
- **지도 화면**: 지도가 전체를 채우고, 그 위에 검색창 + 역 목록 카드가 떠 있는 형태
  - 역 클릭 → 지도 중심 이동 + 주변 장소 마커 갱신
- 스타일은 **Stitch 디자인 토큰**(`frontend/src/index.css`의 `@theme`)을 그대로 사용합니다.
  새 화면을 만들 때 색·폰트·간격을 새로 정의하지 말고 기존 토큰을 재사용하세요.

## 8. API 키 관리

- 카카오 JavaScript 키는 `frontend/.env`에 `VITE_KAKAO_MAP_KEY`로 넣고 코드에서 참조
- `frontend/.env`는 `.gitignore`에 포함 (**절대 커밋 금지**)
- 저장소에는 `frontend/.env.example`만 커밋
- 키 발급 방법과 설정법은 루트 [README.md](../README.md)에 기재

## 9. 구현 순서

1. Vite + React + TypeScript 프로젝트 세팅
2. 카카오맵 SDK 로드 + 지도 표시 (탕정역 좌표 기준 초기 렌더)
3. `stations.json` 작성 + 역 목록 UI
4. 역 클릭 → 지도 중심 이동
5. 선택 역 기준 반경 1km 카테고리 장소 검색 → 마커 표시
6. 마커 클릭 → 인포윈도우
7. 반응형 정리 + README 작성
8. 발표용 프리뷰 화면 3종 (2-1의 노선도 / 경로 / 시간표)

> 각 단계가 끝나면 **실제 브라우저에서 동작 확인 후** 다음 단계로 넘어갑니다.
