# MetroTrip 발표 자료 구성안

발표 분량: **10분**

| 파트 | 시간 | 담당 |
|---|---|---|
| 아이디어 설명 | 3분 | PM |
| **프론트 시연** | **2분** | 프론트 |
| 백엔드 소개 | 5분 | 백엔드 / DB |

> 이 문서는 그중 **앞 5분(아이디어 + 프론트 시연)** 을 다룹니다.
> 뒤 5분(백엔드)은 백엔드 담당이 별도로 준비하며, 연결 지점만 8번 항목에 정리했습니다.

> ⚠️ **프론트 시연은 2분입니다.** 원래 데모 시나리오를 그대로 하면 시간이 넘칩니다.
> 4번의 **압축 시나리오**대로 진행하세요.

---

## 1. 한 줄 소개 (발표 첫 문장)

> "차 없이 지하철만 타고 다니는 사람을 위해, **역을 고르면 그 주변 1km에 뭐가 있는지 지도로 보여주는** 서비스입니다."

## 2. 슬라이드 구성

### 파트 1 — 아이디어 설명 (3분)

| # | 슬라이드 | 핵심 메시지 | 시간 |
|---|---|---|---|
| 1 | 표지 | MetroTrip — 지하철 노선 기반 관광 추천 서비스 / 팀명 / 팀원 | 15초 |
| 2 | 문제 정의 | 자차가 없으면 여행 정보가 '차 있는 사람 기준'으로 나온다 | 50초 |
| 3 | 해결 방안 | 역 중심 반경 1km — 지하철만으로 갈 수 있는 곳만 보여준다 | 50초 |
| 4 | 타깃 & 기대효과 | 자차 없는 20대~사회초년생 / 동네 상권 유동인구 유입 | 40초 |
| 5 | 개발 범위 | 3주 일정 → 1호선 충남권부터. MVP를 의도적으로 좁혔다 | 25초 |

## 3. 슬라이드별 말할 내용

### 2번 — 문제 정의
- 여행 정보를 검색하면 대부분 **자차 이동 기준**으로 나온다.
- 자차가 없는 사용자는 "여기 지하철로 갈 수 있나?"를 매번 따로 확인해야 한다.
- 결과적으로 **역에서 걸어갈 수 있는 거리**의 장소들이 정보에서 소외된다.

### 3번 — 해결 방안
- 발상을 뒤집는다. 장소를 먼저 고르는 게 아니라 **역을 먼저 고른다.**
- 역 반경 1km = 도보로 갈 수 있는 거리.
- 그 안의 음식점 / 카페 / 관광명소만 지도에 표시.

### 5번 — 개발 범위 (아이디어 파트 마무리)
> "전체 노선이 최종 목표지만, **3주라는 기간** 안에서 먼저 증명할 것을 골랐습니다."

- 1호선 → 그중에서도 **천안·아산 구간**(탕정, 아산, 배방, 온양온천, 천안)부터
- 넣은 것: 역 선택 → 지도 이동 → 주변 장소 표시 → 상세 정보
- 뺀 것: 로그인, 게시판, 실시간 지하철 위치, 다크모드 → **못 만든 게 아니라 순서를 미룬 것**
- 근거: `docs/REQUIREMENTS.md` 3장 표

### 7번 — 프론트 기술 구성
```
[사용자] → [React + Vite + TypeScript]
                  ├─ 카카오맵 JS SDK  → 지도 렌더링, 마커
                  ├─ 카카오 로컬 API  → 반경 1km 카테고리 장소 검색
                  └─ stations.json   → 1호선 역 좌표 (정적 데이터)
```
- **지금은 백엔드가 없다**는 점을 명확히 말할 것. 숨기지 말고 "MVP라서 뺐다"로 설명.
- 역 데이터는 정적 JSON → 나중에 **API 호출로만 바꾸면 되는 구조**로 만들었다고 언급.
  → 이 문장이 곧 백엔드 파트로 넘어가는 다리 역할을 합니다.

## 4. 데모 시나리오 (1분 30초 — 압축판)

**2분 안에 끝내야 하므로 4단계로 압축합니다.** 말하면서 조작하지 말고, **조작 → 멈춤 → 설명** 순서로.

| 순서 | 조작 | 말할 것 | 시간 |
|---|---|---|---|
| 1 | 초기 화면 (탕정역) | "지도와 1호선 역 목록입니다" | 15초 |
| 2 | 검색 → 온양온천역 선택 | "역을 검색해서 고르면 지도가 이동하고, **반경 1km 안의 음식점·카페·관광명소**가 바로 표시됩니다" | 35초 |
| 3 | 마커 클릭 | "장소 이름과 주소를 확인할 수 있습니다" | 20초 |
| 4 | 창 크기 줄이기 | "모바일에서도 동일하게 동작합니다" | 20초 |

> **잘라낸 것**: 두 번째 역 선택(갱신 시연). 시간이 남을 때만 추가하세요.
> **데모 역 추천**: 온양온천역 — 주변 상권이 밀집해 마커가 많이 잡혀서 화면이 풍성해 보입니다.
> 탕정역은 마커가 적게 나올 수 있으니 초기 화면용으로만 쓰고, 시연은 온양온천역으로 하세요.

### 데모 사고 방지 체크리스트

발표 **직전에** 반드시 확인:

- [ ] 인터넷 연결 확인 (카카오 API는 온라인 필수)
- [ ] 카카오 개발자 콘솔에 **발표 PC에서 쓸 도메인** 등록되어 있는지 (`localhost` 또는 배포 URL)
- [ ] `frontend/.env`의 `VITE_KAKAO_MAP_KEY` 값이 들어있는지
- [ ] 데모 순서대로 **한 번 리허설** (특히 마커 클릭)
- [ ] 브라우저 콘솔에 에러 없는지
- [ ] **백업**: 데모가 안 될 때를 대비해 화면 녹화 영상 또는 스크린샷 준비
- [ ] 브라우저 확대율 100%, 알림/메신저 끄기

> **API가 죽거나 네트워크가 끊기면** 당황하지 말고 녹화 영상으로 전환합니다. 백업 영상은 필수입니다.

## 5. 예상 질문과 답변

| 질문 | 답변 방향 |
|---|---|
| 왜 로그인이 없나요? | MVP 범위에서 의도적으로 제외. 백엔드 연동 시점(P1)에 추가 예정 |
| 장소 데이터는 어디서 오나요? | 카카오 로컬 API 실시간 조회. 자체 DB 구축은 P1 이후 |
| 1호선 일부만 되나요? | 3주 일정상 천안·아산 구간부터. 역 데이터가 JSON이라 **노선 확장은 데이터 추가만으로 가능**한 구조 |
| 왜 천안·아산 구간인가요? | 팀이 실제로 다니는 생활권이라 결과를 눈으로 검증할 수 있음. 데이터 정확도가 높음 |
| 반경 1km 기준은? | 도보로 이동 가능한 현실적 거리. 추후 사용자가 조절하도록 확장 가능 |
| 다른 지도 API 대비 카카오를 쓴 이유는? | 국내 장소 데이터 정확도, 카테고리 검색 API 제공, 무료 쿼터 |
| 백엔드는 어떻게 붙이나요? | `docs/BACKEND-HANDOFF.md`에 교체 지점 정의 완료 |

## 6. 발표 전 준비물

- [ ] 슬라이드 (이 문서 2번 구성 기준)
- [ ] 데모용 로컬 실행 환경 (또는 Vercel 배포 URL)
- [ ] 데모 백업 영상
- [ ] 발표 대본 1회 이상 리허설
- [ ] **파트 전환 리허설** — 아이디어(PM) → 프론트 → 백엔드로 발표자가 바뀝니다.
      화면 전환과 노트북 교체에서 시간이 새기 쉬우니 전환 지점을 미리 맞춰보세요.

## 7. 시간 배분 주의

프론트 시연은 **2분**입니다. 실제로는 슬라이드 1장 + 데모 1분 30초가 전부입니다.

- 기술 스택을 길게 설명하지 마세요. 스택 나열은 백엔드 파트와 중복됩니다.
- "어떻게 만들었는지"가 아니라 **"무엇이 동작하는지"** 를 보여주는 시간입니다.
- 코드는 띄우지 않습니다. 질문이 나오면 그때 엽니다.
