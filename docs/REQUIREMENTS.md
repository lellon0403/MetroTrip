## 1. 프로젝트 개요 (계획서 요약)

- **목표**: 자차 없이 대중교통(지하철)만으로 이동하는 이용자에게 지하철 기반 저비용 여행 코스 제공
- **방식**: 각 지하철 역 반경 1km 내의 가게·장소·관광지를 추천
- **타깃**: 자차가 없는 20대~사회초년생
- **기대효과**: 동네 상권으로의 유동인구 유입, 저비용 여행 진입장벽 완화

### 팀 구성

| 역할 | 담당 |
|---|---|
| PM | 전세호 |
| 백엔드 | 윤홍규 |
| 프론트엔드 | 우진, 황지성 |
| DB | 김유진 |

### 개발 환경 (계획서 기준)

| 구분 | 스택 |
|---|---|
| 프론트 | React (Vercel 배포) |
| 백엔드 | RESTful API |
| DB | MySQL / Oracle |
| DevOps | Docker, Kubernetes, GitHub Actions |
| 협업 | Git, GitHub, Notion, Discord |

## 2. 단계 구분

전체 프로젝트 기간은 **3주**입니다. 최종 목표는 전체 노선 지원이지만,
기간을 고려해 **1호선 → 그중 천안·아산 구간**부터 좁혀서 시작합니다.

- **P0 (MVP / 발표)**: 이번 발표에서 시연할 범위. 프론트 단독, 백엔드 없음.
- **P1**: 백엔드 연동 후 바로 붙일 기능.
- **P2**: 그 이후 확장 기능.

### 노선 범위 확장 순서

| 단계 | 범위 |
|---|---|
| 지금 (P0) | 1호선 천안·아산 구간 (탕정, 아산, 배방, 온양온천, 천안 등) |
| 다음 | 1호선 전 구간 |
| 최종 | 수도권 전철 1~9호선 |

> 역 데이터가 정적 JSON이라 **노선 확장은 데이터만 추가하면 됩니다.** 코드 구조를 그렇게 유지하세요.

### P0 — 발표 MVP (프론트만)

| 구분 | 요구사항 | 비고 |
|---|---|---|
| 공통 | 역 검색 (이름 기준) | 정적 JSON 기반 |
| 공통 | 역 선택 | 목록 / 검색 결과에서 선택 |
| 공통 | 선택 역 반경 1km 장소 표시 | 카카오 로컬 API 직접 호출 |
| 공통 | 장소 카테고리 (음식점/카페/관광명소) | FD6 / CE7 / AT4 |
| 공통 | 반응형 웹 (PC 1920px, 모바일 360px) | flex 기반 간단 구현 |

상세 조건은 [SPEC.md](SPEC.md) 참조.

## 3. MVP에서 의도적으로 뺀 것과 이유

| 뺀 기능 | 이유 |
|---|---|
| 로그인 / 회원가입 | 백엔드·DB 필요. 데모 흐름에 불필요 |
| 후기·소모임 게시판 | 저장소(DB) 필요 |
| 실시간 지하철 위치 | WebSocket + 외부 실시간 API. 1주일 내 리스크 과다 |
| 전체 노선도 SVG | 제작 공수가 큼. 역 목록으로 대체 가능 |
| 다크모드 | 데모 가치 대비 공수 낮음 |

> 발표 때 "왜 안 만들었나" 질문이 나오면 **"MVP 범위를 의도적으로 좁혔고, 다음 단계 계획이 있다"** 로 답합니다.
> 근거는 이 표와 [PRESENTATION.md](PRESENTATION.md)에 정리되어 있습니다.
